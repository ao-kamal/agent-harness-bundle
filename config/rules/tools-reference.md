# Installed Tools & Skills — Operational Reference

Split from the global CLAUDE.md 2026-07-30 (gotchas preserved verbatim; version pins dropped where they only drift; new tools appended). Updates and per-tool repos: keep a tooling-update-runbook in your knowledge base and read it before any update run.

## Key skills

- **defuddle** — CLI for main-content extraction + clean markdown (bin at `C:\Users\{{WIN_USER}}\AppData\Roaming\npm\defuddle.cmd`). Its own algorithm (NOT Mozilla Readability): entry-point selector priority list (`article` > `main` > `#content` > `body`), strips via 200+ exact CSS selectors + ~300 partial class/id regexes, smart retry on thin pages; returns only the article body.
  - **Command:** `defuddle parse <source> --md` (markdown); `--json` for metadata+content; `--property title` for a single field; `-o <file>` to write out.
  - **Input modes:** local FILE PATH **or** URL only — **NO stdin** (passing `-` = ENOENT). To clean ALREADY-FETCHED HTML, write it to a tempfile and pass the path.
  - **JS render: NO** — static HTML only. JS-injected SPAs yield little/no content; render first (dev-browser / firecrawl), THEN clean the rendered HTML with defuddle.
  - **Python integration:** write HTML to a tempfile, then `subprocess.run(f'defuddle parse "{tmp}" --md', shell=True, capture_output=True, text=True)`, read stdout.
  - **Limitations:** fails on raw GitHub `raw.githubusercontent.com` URLs (plain text, not HTML — use `WebFetch`/`curl`); cannot extract JS-rendered content; no stdin.
  - **Package-name split:** Windows npm package is `defuddle`; the WSL/Linux npm package is `defuddle-cli` — two different package names for the same tool. Get it wrong and the install "succeeds" with the wrong thing.
- **firecrawl** — Web scraping, search, crawl, map. Skill at `~/.claude/skills/firecrawl/`. Auth via `FIRECRAWL_API_KEY` env var (now lives in `.env.private` — see rules/windows-commands.md → Secrets). Results are written to `.firecrawl/` files to avoid flooding context.
  - **CLI:** Command is `firecrawl` (NOT `firecrawl-cli`, despite the npm package being named `firecrawl-cli` on Windows).
  - **Python SDK:** `firecrawl-py` (v4+ API). `from firecrawl import Firecrawl`; `app = Firecrawl(api_key=...)`; `app.scrape(url, formats=['markdown'])` → `result.markdown`; `app.batch_scrape(urls, ...)` → `job.data`; async via `app.start_batch_scrape` + `app.get_batch_scrape_status(job.id)`; `app.map(url)`; `app.search(query)`. Returns Pydantic models — attribute access, not `.get()`. **Pre-v4 methods `scrape_url` / `batch_scrape_urls` no longer exist.**
  - **In scripts:** Use the Python SDK (not subprocess CLI calls) for reliability. If you maintain multiple firecrawl accounts/keys with independent credit balances, rotate to a fresh one on "Insufficient credits" rather than assuming firecrawl is down.
- **Jeffrey's Skills.md** — many skills in `~/.claude/skills/` originate from the jsm marketplace (paid subscription). Key families: `beads-br`/`beads-bv`/`beads-workflow` (task graphs), `idea-wizard`, `planning-workflow`, `cass`/`cass-memory`, `de-slopify`/`docs-de-slopify`, `operationalizing-expertise`, `repeatedly-apply-skill`.

## CLI tools

- **cass** — Search all coding agent session history (Claude Code, Codex, Gemini, Cursor, etc.) from a unified index. Both sides (`~/.local/bin/cass` Win, `/root/.local/bin/cass` WSL). **NEVER run bare `cass`** — TUI; always `--robot` or `--json`. See `cass` skill for usage and recovery. Windows-specific operational state:
  - **Updating:** official `install.ps1` over scoop (scoop manifest historically stale); `-ExecutionPolicy Bypass` required. If cass.exe is locked by the daemon: stop the Cass Watch Daemon task first, then retry.
  - **Runtime pattern: ONE long-lived `cass index --watch` daemon. Never schedule `cass index` on a repeat interval.** A repeat-interval task + corrupt DB can accumulate a huge number of backups very fast (retention logic skips cleanup when `create_backup` partially succeeds) — one real case hit 25 backups × 3.5 GB = 77 GB before detection. The daemon lives in the **`Cass Watch Daemon`** scheduled task (logon trigger → `wscript.exe C:\Users\{{WIN_USER}}\.local\bin\cass-watch-hidden.vbs`; the VBS skips spawning if cass.exe already runs). Manage: `Stop-ScheduledTask 'Cass Watch Daemon'` + `taskkill /F /IM cass.exe`; `Start-ScheduledTask` to start. Task state reads `Ready` even while running — verify via `Get-Process cass`.
  - **DB corruption recovery:** `cass doctor --fix --json` (backs up bad DB+WAL, rebuilds derived data, leaves DB empty → follow with `cass index`). Do NOT use `cass index --full --force-rebuild` on Windows (Access Denied on backup step).
- **cm (cass-memory)** — Procedural memory layered on cass. Run `cm context "<task>" --json` before any non-trivial task. Both sides. See `cass-memory` skill.
- **br (beads_rust)** — Local-first issue tracker with dependency graphs. SQLite primary + JSONL committed to git via `.beads/`. Both sides. **NEVER run bare `br`** without a subcommand. See `beads-br` skill. `.beads/` must live on ext4 in WSL projects (hot/cold rule — rules/wsl-patterns.md).
- **bv (beads_viewer)** — Graph-aware triage engine for beads (PageRank, critical path, cycles, parallel tracks). Both sides. **NEVER run bare `bv`** — TUI; always `--robot-*`. See `beads-bv` skill.
- **jsm** — Marketplace CLI for the Jeffrey's Skills.md library (paid subscription; skills land in the shared skills dir both OSes read). WSL is the operationally-current install; run via `wsl -d Ubuntu -u root -- bash -l`. Robot mode is `--json`, not `--force` (`--force` = "re-install even if up to date"). Key commands: `jsm list`, `jsm search "query"`, `jsm install <skill-id> --json`, `jsm sync --force`, `jsm sync --status`.
- **caam** — Sub-100ms account switching for AI coding CLIs. Scoop on Windows + WSL copy; vault shared cross-OS via symlink. **`caam run` does NOT work on Windows** (Unix PTY syscalls) — manual workflow: hit rate limit → exit Claude Code → `claude-swap` (alias for `caam activate claude --auto`) → relaunch `claude`. Git Bash aliases: `claude` (adds `--dangerously-skip-permissions`), `claude-swap`. Claude Max has a 5-hour rolling window — when you hit it, switch accounts. See `caam` skill (its `caam run` alias recommendation does not apply on Windows).
- **ms (Meta Skill)** — Skill lifecycle management: hybrid search, effectiveness tracking, provenance, anti-pattern mining, token packing, graph analysis. Windows (`scoop\shims\ms.exe` — NOT actually scoop-tracked; the real installer is the repo's `scripts/install.sh`, its published scoop/homebrew manifests are broken placeholder stubs). **`-m` for JSON output, NOT `--robot`** (README documents `--robot`; the binary uses `-m`/`--machine`). Config: `%APPDATA%\ms\config.toml`. Core commands: `ms search "<q>" -m`, `ms show <id> --meta -m`, `ms index <path>`, `ms validate <id> -m`, `ms load <id> --pack 4000 -m`, `ms feedback add <id> --positive/--negative --comment "..."`, `ms outcome <id> --success/--failure`, `ms prune analyze -m`, `ms suggest -m`. ms owns the platform (index/search/track/prune); skill-forge owns the creation workflow and calls ms when available.
- **bw (Bitwarden CLI)** — THE credential store for client/agent credentials (npm global, shim at `%APPDATA%\npm\bw.cmd`). Client credentials (cPanel, registrars, API tokens) live here as named items, not in files or chat.
  - **Every call needs the session key:** `source ~/.env.private && bw <cmd>` — `BW_SESSION` is exported there. Shell state doesn't persist between tool calls, so the `source` prefix goes on every invocation.
  - **NEVER run `bw login` / `bw unlock` (or any prompting bw command) from the agent** — non-TTY kills inquirer with `ERR_USE_AFTER_CLOSE`. Interactive steps are the user's, in their own terminal. **If a bw call exits 1 with a "Master password" prompt in stderr, the session key is stale/locked:** ask the user to run `bw unlock` in a terminal and refresh the `BW_SESSION` line in `~/.env.private`.
  - **From Python `subprocess`, use the full shim path** `r'C:\Users\{{WIN_USER}}\AppData\Roaming\npm\bw.cmd'` — argv-list `['bw', ...]` gets `FileNotFoundError` (CreateProcess can't resolve npm shims).
  - **Read:** `bw get password "<item name>"` · `bw list items --search <q>` (JSON incl. passwords — never print raw; extract names/fields only). **Write:** JSON item → base64 → `bw create item <b64>` (item template: `{'type':1,'name':...,'notes':...,'login':{'username':...,'password':...,'uris':[{'uri':...}]}}`). Verified round-trip incl. `bw delete item <id>`.
  - Convention: secrets pasted in chat get filed to the vault immediately, with source/date in notes; deliberate `.env.private` exports (working-session tokens) are the only mirror. `bw lock` kills agent access until the user re-unlocks.
- **ctx7 (Context7)** — CLI for current library docs; invoked through the `find-docs` skill (two-step: `ctx7 library` → `ctx7 docs`). No MCP server — CLI only. Full usage contract: rules/context7.md.
- **fw (franken_whisper)** — Local speech-to-text + speaker diarization. **No Claude Code skill** — do not invoke `/fw` or `/franken_whisper`. Pure-Rust Whisper + Sortformer. No Python, no upload. Site: https://franken-whisper.com/ · repo: `Dicklesworthstone/franken_whisper`. Bins: `C:\Users\{{WIN_USER}}\.local\bin\fw.exe` and `franken_whisper.exe` (same binary, two names). On Windows PowerShell, `fw` can resolve to `Format-Wide`; call the `.exe` path.
  - **Command:** `fw transcribe --input audio.mp3 --json` · `fw robot run --input audio.mp3` (NDJSON) · `--no-persist` until you want SQLite history.
  - **Agent surface:** `fw --version` · `fw robot triage` · `fw capabilities --json` · `fw models --json` · `fw doctor --json` · `fw robot-docs guide`. Never scrape human help first.
  - **Models:** not in the zip. Live under `%LOCALAPPDATA%\franken_whisper\models\` (`whisper/whisper-large-v3-turbo-f16-v1/ggml-large-v3-turbo.bin`, `sortformer/sortformer-v2.1-f32-v1/weights.safetensors` + receipt + NVIDIA license). Official tags: `whisper-large-v3-turbo-f16-v1`, `sortformer-v2.1-f32-v1`. `fw doctor --json` `ready:true` means both packages hashed; `operationally_verified` stays false until a real transcription.
  - **Install / update (Windows):** README `install.sh` is Linux/macOS/WSL only. Grab `windows_amd64.zip` + `.sha256` from the latest GitHub release, copy both exes to `.local\bin`, `Unblock-File`. **Do not use `fw pull all` as the default on a throttled machine** — session-killed / throttled. BITS the two model-release assets into the cache paths above, then SHA-256 against the compiled pins (`fw models --json`). ECAPA is optional and not published; skip unless asked.
  - **Also:** in-browser playground on the site (same engine, ~1.3 GB weights stay in the tab). ffmpeg already on PATH via scoop for video/exotic codecs.
- **fmd (franken_markdown)** — **THE default for Markdown → PDF** (or self-contained HTML) deliverables. **No Claude Code skill** — do not invoke `/fmd` or `/franken_markdown`. Clean-room Rust renderer, no browser/LaTeX/Pandoc. `C:\Users\{{WIN_USER}}\.local\bin\fmd.exe`.
  - **Command:** `fmd input.md --to pdf --title "..." --author "{{USER_FULL_NAME}}" --out output.pdf --json` · `--to both` writes HTML + PDF · default is HTML.
  - **Gotchas:** PDF cannot stream to stdout — needs a real `--out`; bare `fmd` prints help (never a TUI); raw HTML escaped by default (`--allow-html` only for trusted input); `--json` status → stderr, document bytes → stdout; deterministic PDFs via `SOURCE_DATE_EPOCH=<secs>` + `--no-config`.
  - **Agent surface:** `fmd capabilities --json` · `fmd doctor --json` · `fmd robot-docs guide` · `--robot-triage`. Config at `%APPDATA%\fmd\config`.
  - **Install/update gotcha:** official `install.ps1` fails to resolve releases (falls back to cargo source build). Working path: `gh release download` the `x86_64-pc-windows-msvc.zip` + verify `.sha256` + copy to `.local\bin` (BITS on throttled network).
  - **Client-doc practice:** before converting an internal doc for a CLIENT, grep it for engagement-internal content (names, pricing, proposal references) first.
- **slb (Simultaneous Launch Button)** — Two-person rule for dangerous commands in multi-agent workflows. Both sides (Windows `.local\bin\slb.exe`, WSL `/root/.local/bin/slb`). Version via `slb version` (subcommand — `--version` exits 1). Per-project `slb init`; agents request via `slb run "<cmd>" --reason "..."`, peers approve. **Global Claude Code hook deliberately NOT installed** (fail-closed; solo sessions would break) — swarm-only via AGENTS.md instructions. See rules/ntm-swarm.md → Swarm conventions.
- **PCR (post-compact reminder)** — Installed both sides. WSL: upstream installer (`~/.local/bin/claude-post-compact-reminder`, AGENTS.md-focused message). Windows: Python port at `~/.claude/hooks/post-compact-reminder.py` (CLAUDE.md-focused message), registered as a SessionStart/compact hook. Customize messages by editing the script (no restart needed).
- **SRPS (system resource protection)** — WSL, partial install (no systemd in this WSL → ananicy service and `limited*` aliases skipped; `ENABLE_ANANICY=0`). Live pieces: sysctl responsiveness tuning (`/etc/sysctl.d/99-system-resource-protection.conf`) + `sysmoni` (TUI monitor; non-TTY auto-emits JSON; `--json`/`--json-stream`), `check-throttled`, `srps-doctor` — all in `/usr/local/bin`. Installer refuses root: re-run upgrades as the dedicated `srps` user (`su - srps -c 'bash /home/srps/install.sh --install'`; NOPASSWD sudoers drop-in `/etc/sudoers.d/90-srps-install` exists for this).
- **branch-back** — Forks a Claude Code session at an arbitrary past JSONL message. `~/.local/bin/branch-back` + `.cmd` shim; WSL executes the same file via /mnt/c. See `branch-back` skill.

## Working with Data-Heavy MCP Tools

When using tools that return large datasets (especially social media scrapers), start with minimal parameters to avoid token limits: begin with small result counts (3-5 items), disable comments/reactions initially, use pagination or field filtering for detailed analysis, iterate rather than pulling everything at once.

## Web testing

- **dev-browser** skill/CLI is the canonical primary tool for browser automation (auto-triggers on browser/screenshot/scrape/visual-verification tasks).
- **Fixed viewport for screenshots**, derived from your actual hardware (device resolution → Windows display-scaling factor → effective resolution → minus ~60px browser chrome). Work out this number once for your own screen and always set it before screenshots, so visual verification matches what you actually see: `await page.setViewportSize({ width: <W>, height: <H> });`. (Example: a 15" 1920×1080 laptop at 150% scaling → effective 1280×720 → minus chrome → 1280×660.)

## Code review (CodeRabbit PRs)

When addressing CodeRabbit comments on pull requests: ALWAYS IGNORE comments about planning docs, CLAUDE.md files, TaskMaster files, or documentation. ONLY FIX comments on actual application code (bugs, security, performance, type safety, error handling). Skip markdown formatting suggestions in documentation files.
